# Развёртывание на Bothost

## 1. Подготовьте Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Узнайте свой Telegram ID и сохраните его для `SUPERADMIN_ID`.
3. Если нужны ответы в группах без упоминания бота, откройте настройки бота у BotFather и отключите Group Privacy (`/setprivacy` → Disable).

## 2. Загрузите проект на GitHub

1. Распакуйте архив проекта.
2. Создайте на GitHub пустой репозиторий, например `sgugit-bot`.
3. Загрузите **содержимое папки `sgugit-bot`** в корень репозитория — не добавляйте дополнительную вложенную папку `sgugit-bot/`.
4. Убедитесь, что в корне видны `Dockerfile`, `requirements.txt`, `README.md` и папка `app/`.
5. Не загружайте `.env`, токен, базу данных или резервные копии. `.gitignore` уже исключает их.

## 3. Создайте приложение на Bothost

1. Откройте [Bothost](https://bothost.ru/) и создайте нового Telegram-бота из Git-репозитория.
2. Укажите URL репозитория и ветку `main` (или ту ветку, в которую загрузили проект).
3. В дополнительных настройках включите использование Dockerfile из репозитория. В проекте уже есть подходящий `Dockerfile`; команда запуска — `python -m app.main`.
4. Если панель просит указать главный файл/команду запуска вручную, укажите `python -m app.main` и установите рабочую директорию в корень репозитория (там, где находится папка `app`). Не указывайте `app/main.py` как файл запуска, если можно задать команду. В этой версии добавлена страховка для запуска файлом напрямую, но рекомендуемый вариант — `python -m app.main`. При включённом собственном Dockerfile фактическая команда задаётся в `CMD` файла.

## 4. Добавьте переменные окружения

В настройках приложения Bothost добавьте:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather — секрет, не публикуйте его |
| `SUPERADMIN_ID` | Ваш числовой Telegram ID |
| `DATABASE_URL` | `sqlite:///data/bot.db` |
| `TIMEZONE` | `Asia/Novosibirsk` |
| `SYNC_INTERVAL_MIN` | `30` |
| `LOG_LEVEL` | `INFO` |
| `BACKUP_DIR` | `data/backups` |

Остальные параметры уже имеют значения по умолчанию; при необходимости смотрите `.env.example`.

**Важно о базе:** путь `sqlite:///data/bot.db` указывает на `/app/data/bot.db` в рабочем каталоге приложения. В Bothost храните рабочую SQLite-базу в специальной постоянной папке `data`, которая не перезаписывается при обновлении кода. Проверьте в панели Bothost, что хранилище `data` включено и доступно для записи. Для внешней PostgreSQL вместо SQLite задайте полный `DATABASE_URL` от вашего провайдера базы данных.

## 5. Запустите и проверьте

1. Выполните деплой и откройте логи приложения.
2. Если запуск завершился ошибкой, проверьте, что заданы обе обязательные переменные: `BOT_TOKEN` и `SUPERADMIN_ID`, а зависимости установились.
3. Найдите бота в Telegram и отправьте `/start`.
4. С аккаунта главного администратора отправьте `/admin`.
5. Для первого запуска используйте тестовую группу/данные, проверьте регистрацию, выбор группы и расписание. Сайт вуза может менять разметку; при необходимости загрузите расписание через админ-панель.

Запускайте **только один экземпляр** бота с этим токеном: несколько процессов polling могут конфликтовать.

## 6. Обновление проекта

Отправляйте изменения в выбранную ветку GitHub и запускайте redeploy в Bothost. Не коммитьте `.env`, `data/bot.db`, файлы резервных копий и реальные пользовательские данные. Перед серьёзным обновлением сделайте резервную копию базы.

## Переменные окружения для локального запуска

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните BOT_TOKEN и SUPERADMIN_ID в .env
python -m app.main
```

Windows PowerShell: вместо `cp` можно выполнить `Copy-Item .env.example .env`.

## Дополнительно

- Форматы импорта: `docs/IMPORT_FORMAT.md`.
- Разбор официального сайта: `docs/SITE_PARSER.md`.
- Для локального запуска PostgreSQL через Docker Compose: `docker compose up --build` после настройки `.env`.
- Бот по умолчанию использует long polling, поэтому домен и открытый порт для обычного запуска не нужны.
